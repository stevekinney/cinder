# Dropdown Accessibility

## Provenance

This record was rewritten on 2026-09-22 against the component source and test suite current on this branch (`dropdown.svelte`, `dropdown-menu.svelte`, `dropdown-item.svelte`, `dropdown-trigger.svelte`, and their `*.test.ts` files). The previous revision described an earlier, simpler implementation ("arrow navigation not yet implemented", "focus remains on the trigger") that arrow-key navigation, typeahead, and initial-focus-on-open work has since superseded. It documents source and `bun:test`/happy-dom evidence only — see "What has not been verified" below for what a human or assistive-technology pass would still need to confirm.

Dropdown ships two composition modes that share one context (`dropdown.context.ts`) but render different markup:

- **Legacy snippet API** — a bare `<Dropdown open trigger children>` where the consumer's `trigger`/`children` snippets own their own markup and Dropdown only wires ARIA attributes onto the first focusable descendant of `trigger`.
- **Compound API** — `<Dropdown><DropdownTrigger/><DropdownMenu><DropdownItem/>…</DropdownMenu></Dropdown>`, where DropdownTrigger and DropdownMenu render the interactive/menu markup themselves.

## Roles, names, and states

- The trigger is a `<button>` (compound API: `dropdown-trigger.svelte`) or the consumer-supplied focusable element (legacy API). Both carry `aria-haspopup="menu"`, `aria-expanded` synced to open state, and `aria-controls` pointing at the menu id (`dropdown-trigger.svelte:74-77`; legacy wiring at `dropdown.svelte:121-136`, asserted by `dropdown.test.ts` "compound trigger wires menu ARIA to the button" and "legacy trigger wrapper does not own aria-haspopup"/"…aria-expanded"). When the Popover API is supported, the trigger also gets `popovertarget`.
- The open menu carries `role="menu"` and `aria-orientation="vertical"` (`dropdown-menu.svelte:284-285`; compound case asserted by `dropdown.test.ts` "compound menu renders labels, separators, and items"; legacy case by "menu has role=\"menu\"").
- **Compound API items** get their role from `DropdownItem`'s `itemRole` prop, which defaults to `"menuitem"` and also accepts `"menuitemcheckbox"`/`"menuitemradio"` (`dropdown-item.svelte:34`, applied at `dropdown-item.svelte:137,156`); `aria-checked` is set only for the checkbox/radio roles (`dropdown-item.svelte:122-124`). `dropdown.test.ts` "compound menu renders labels, separators, and items" asserts 3 `[role="menuitem"]` items and 2 `[role="group"]` regions with `aria-labelledby` pointing at rendered `DropdownLabel` text ("grouped menu exposes aria-labelledby boundaries").
- **Legacy API children** render raw consumer markup inside the menu; Dropdown does not assign item roles for this path; the consumer is responsible for `role="menuitem"`/`"menuitemcheckbox"`/`"menuitemradio"` on each interactive child. This is unchanged from the prior revision of this record.

## Keyboard interactions

| Key                            | Behavior                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Enter / Space                  | Activates the trigger, opening the menu. In the compound API, activating a focused `DropdownItem` fires its native click, closing the menu (`dropdown.test.ts` "Enter activates the focused menu item and closes the menu").                                                                                                                                                                                                                                                |
| Escape                         | Closes the open menu and returns focus to the trigger (both APIs — see "Focus management" below).                                                                                                                                                                                                                                                                                                                                                                           |
| Tab                            | Legacy API: moves focus out of the dropdown, closing the menu (follows the ARIA menu-from-button pattern; unimplemented navigation-within-menu note from the prior revision no longer applies to the compound API, see next row). Compound API: `DropdownItem` keeps `tabindex="-1"` and is reached only through arrow/Home/End roving focus, so Tab is not part of its navigation model.                                                                                   |
| Arrow Up / Down (compound API) | Moves roving focus across `[role="menuitem"/"menuitemcheckbox"/"menuitemradio"]` descendants, skipping `data-disabled` items, and wraps at both ends (`dropdown-menu.svelte:226-264`, `getOwnedMenuItems`/`focusMenuItem`). Wrapping and cross-group movement are asserted by `dropdown.test.ts` "ArrowDown and ArrowUp move across grouped menu boundaries", "ArrowUp from the first item wraps to the last item", "ArrowDown from the last item wraps to the first item". |
| Home / End (compound API)      | Moves focus to the first/last enabled item (`dropdown-menu.svelte:242-249`; asserted by `dropdown.test.ts` "Home and End land on the first and last enabled grouped menu items").                                                                                                                                                                                                                                                                                           |
| Typeahead (compound API)       | Printable-character keys buffer via `TypeaheadBuffer` and jump focus to the next item whose label starts with the buffered text (`dropdown-menu.svelte:250-263`, `utilities/typeahead.ts`).                                                                                                                                                                                                                                                                                 |
| Arrow Up / Down (legacy API)   | Not implemented — Dropdown does not attach key handlers to legacy `children`. The prior revision's "not yet implemented" note is accurate for this path only.                                                                                                                                                                                                                                                                                                               |

## Focus management

- **Initial focus, compound API:** on open, focus moves to the first enabled item by default; `Dropdown`'s context exposes `initialFocus?: 'first' | 'last' | 'none'` (`dropdown.types.ts:16`) for the fallback (non-popover) path, wired in `dropdown-menu.svelte:126-135` and, for the native-popover `toggle` event, `dropdown-menu.svelte:266-274`. `dropdown.test.ts` "compound fallback menu focuses the first enabled item when opened" asserts the default. The root `Dropdown` component (`dropdown.svelte:111-113`) always reports `initialFocus: undefined` (equivalent to `'first'`); no shipped consumer currently opts into `'last'`/`'none'`, so those branches are exercised only by `dropdown-menu.test.ts`, not by an end-to-end `Dropdown` consumer.
- **Initial focus, legacy API:** unchanged from the prior revision — focus remains on the trigger when the menu opens; there is no first-item auto-focus for this path.
- **Escape return, both APIs:** Escape closes the menu and restores focus to the trigger. The compound path is `dropdown-menu.svelte`'s `dismissMenu` (non-popover) and its native-popover Escape handler (`dropdown-menu.svelte:186-224`); the legacy path is `dropdown.svelte`'s `dismissLegacyFallbackMenu` and its native-popover handler (`dropdown.svelte:178-228`). Both explicitly re-focus the trigger even when focus had already left the menu before Escape was pressed — a regression the prior record's flat "focus returns to the trigger automatically since it was never moved" claim did not anticipate for that case. Covered by `dropdown.test.ts`: "CIN-428 (legacy non-popover branch): Escape restores focus to the trigger when focus already left the menu (review finding)" (line ~285), "compound fallback menu restores focus to trigger on Escape" (line ~503), "Escape with focus on trigger (outside menu) still closes compound menu" (line ~522), "Escape on compound menu does not double-fire close+focus through parent handler" (line ~573), and the native-popover-branch describe block's "Escape restores focus to the legacy trigger when focus already left the menu (review finding)" (line ~963).
- **Escape ownership / stacking:** both APIs register on a shared LIFO escape stack (`_internal/overlay.ts`) instead of a menu-scoped listener, so a nested or sibling overlay's Escape handler is not incorrectly triggered. See `dropdown.test.ts` "CIN-428 (legacy non-popover branch): holds a pushEscapeHandler registration…" and "CIN-428 (modern/compound branch): inherits escape-stack registration transitively from DropdownMenu…".

## Comparison to the DropdownMenu / DropdownItem pattern

Dropdown's compound API _is_ DropdownMenu/DropdownItem — `dropdown-menu.svelte` and `dropdown-item.svelte` are the menu-surface and row primitives Dropdown composes, not a separate parallel implementation. That composition already implements the full WAI-ARIA menu pattern's roving-focus keyboard matrix (arrows, Home/End, typeahead) that the prior record said was unimplemented. The one gap against the full menu pattern is the legacy snippet API, which intentionally delegates all item semantics and menu-internal key handling to the consumer and is not expected to gain roving focus — consumers who need the full keyboard matrix should use the compound API instead.

## Popover API path

Unchanged from the prior revision: when the browser supports the Popover API (`showPopover`/`hidePopover`) and CSS Anchor Positioning, the menu uses `popover="auto"`, giving the browser control over showing/hiding and built-in light-dismiss. The `toggle` event syncs the browser's popover state back to the bindable `open`/context state. `happy-dom` does not implement the Popover API, so `dropdown.test.ts` stubs `showPopover`/`hidePopover` on `HTMLElement.prototype` to exercise this branch (see the "Dropdown legacy native-popover branch" describe block and the file-level `NOTE` above it).

## Outside-click dismissal

Unchanged from the prior revision: in the non-popover fallback, a `click` listener is attached to `document` while the menu is open and removed when it closes (`createClickOutside` in `dropdown.svelte`).

## What has not been verified

This record reflects source reading and the `bun:test`/happy-dom suite only. The following have not been confirmed in a real browser or with assistive technology, and are tracked by the CIN-563 audit ledger rather than claimed here:

- Actual screen-reader announcement of typeahead jumps, group boundaries, or checkbox/radio state changes.
- Native Popover API light-dismiss and `toggle`-driven focus restoration end-to-end (the test suite stubs `showPopover`/`hidePopover`; it does not run in a browser that implements the real Popover API and CSS Anchor Positioning together).
- Touch/pointer behavior on the compound trigger caret and menu items.
