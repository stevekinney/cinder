`ImageLightbox` now composes `@lostgradient/cinder`'s `Modal` (in its new chromeless mode) instead of hand-rolling its own dialog shell. The public `ImageLightboxProps` are unchanged, but the underlying behavior is observably different: Escape now dismisses the lightbox through the shared LIFO escape stack (`_internal/overlay.ts`'s `pushEscapeHandler`), so when the lightbox is nested under another overlay (e.g. opened from inside a Drawer) Escape only closes the top-most one — previously the lightbox's own hand-rolled `keydown` listener bypassed the stack and could close underneath an overlay that should have taken priority. The body-scroll lock is now acquired/released entirely by Modal's `SlidingDialogState` rather than the lightbox's own `createBodyScrollLock()` attachment (still the same counted lock, so nested-overlay scroll restoration is unaffected). Focus trapping is now Modal's shared focus trap rather than the lightbox's own `createFocusTrap()` attachment; initial focus lands on `.lightbox-content` itself (via `autofocus`), which the lightbox sets specifically so it becomes Modal's initial-focus target instead of Modal's own body wrapper — otherwise ArrowLeft/ArrowRight navigation would not work until focus moved somewhere inside the panel. The lightbox's own JS-driven fade transition (previously deriving its duration from `useReducedMotion()`) is removed in favor of Modal's own CSS-driven enter/exit transition, which already collapses under `prefers-reduced-motion: reduce`. The displayed image and navigation position are now retained through the whole exit transition (previously they could reset to `initialIndex` mid-fade the instant a close began) — the reset to `initialIndex` happens only on the next fresh open. `chrome="none"` is exposed as a new prop on Modal — this is called out separately in the `@lostgradient/cinder` changeset.
