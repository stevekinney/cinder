# Theme builder token capabilities

This document describes the private authoring catalogue generated from the Cinder token corpus. The generated data is [`theme-token-registry.generated.ts`](../packages/playground/src/shell-app/theme-token-registry.generated.ts) and is separate from the public runtime boundary owned by CIN-572. The matrix records current schema, resolver, and CSS serializer evidence separately from the future CIN-572 runtime and CIN-581 portable-export work. There is no complete portable-export command in this checkout.

## Catalogue contract

Every public registry entry appears exactly once in the generated catalogue. The catalogue records authored source values, effective type for each concrete context, ordered source locations, direct dependencies, CSS usage contracts, and three export dispositions. Private `--_cinder-*` variables and unknown imported CSS bindings are not catalogue entries. Every public Cinder entry requires authored usage contracts; missing contracts fail generation. Optional source metadata remains `null` or an empty list instead of being inferred from a token name.

The six evaluated contexts are `light/default`, `light/reduced`, `light/forced-reduced-motion`, `dark/default`, `dark/reduced`, and `dark/forced-reduced-motion`. Source locations use normalized document IDs, canonical token paths, exact JSON Pointers, and zero-based positions in the expanded source list. The catalogue calls the existing generation resolver; it does not introduce a parallel evaluator.

Both portable dispositions require every context to be representable. A failure in any context omits the aggregate value and names each affected context and reason. When all contexts are representable, the aggregate value projects `light/default`; each context record retains its own resolved value and recipe inputs for later export selection.

## CSS usage review

Token generation scans owned source under the components, chat, editor, markdown, and Playground packages, plus `labs/chat-room/src`. Production examples and fixtures are included; established test directories and test, spec, Playwright, and e2e filenames are excluded. The inventory follows public and private custom-property references to terminal CSS declarations, including static Svelte styles, JavaScript style mutations, and SVG presentation attributes. SVG gradient stops use the color contract defined by [SVG 2's `stop-color` property](https://www.w3.org/TR/SVG2/pservers.html#StopColorProperty).

Shared stylesheet composition preserves known state-pseudo conditions and the originating element for `::before` and `::after`, with stylesheet ownership and pseudo-element isolation. Functional pseudos remain outside that matcher. Response bodies with explicit, unambiguous JSON, NDJSON, event-stream, or plain-text MIME headers are excluded from HTML traversal; unknown or dynamic headers still require inspection.

Dynamic expressions require an explicit entry in [`css-usage-review.json`](../packages/components/scripts/tokens/css-usage-review.json). Each entry identifies the exact source location and expression, its owned producer, any intermediate producer files, and the public token mappings that reach the terminal CSS property. Caller-supplied CSS, browser-computed color strings, and numeric layout values carry no invented public binding. Computed colors have a separate review category because their owned producer reads resolved values rather than emitting public `var()` references. Generation rejects missing or stale entries, changed source or producer hashes, contradictory classifications, unknown token mappings, and unaccounted parser diagnostics.

Run this command from the repository root to inspect the current inventory:

```bash
bun packages/components/scripts/tokens/css-usage-inventory-command.ts --output /tmp/cinder-css-usage-inventory.json
```

Inspect changed expressions and their producer chains before updating the review sidecar. Add every observed CSS property to the affected token's authored `usageContracts`, using an existing compatible profile or a reviewed new property grammar. Regenerate with `bun run --filter=@lostgradient/cinder tokens:generate`, then verify with `bun run --filter=@lostgradient/cinder tokens:check`. The generated catalogue records the observed properties separately from declared contracts for consumer use.

The resolver fixture coverage also includes `$root`, inherited types, two-hop aliases, `$extends`, references, shared/theme/motion precedence, repeated sources and reset. `profile.resolver.json` exercises the six concrete theme/motion combinations through the production load, validation, and context-expansion primitives; the test asserts independent theme and motion fields and source preservation. `css-only.tokens.json` exercises authored CSS recipes without presenting their source values as substituted CSS keywords or claiming those recipes are portable DTCG values. Unsupported profile behavior is an explicit disposition rather than a standards conformance failure.

The unbound imported-source fixture in `theme-builder-capabilities.test.ts` runs schema validation and traced resolution in all six contexts. It preserves the token's typed value, source identity and unknown extensions without inventing a CSS binding. This proves source evaluation, not an imported-draft catalogue or export command. The shipped-corpus registry currently requires a `cssProperty` for every base token; CIN-572 owns evaluating unbound draft tokens and public aliases to them through explicit public bindings. CIN-581 owns source-envelope and portable export products.

## CSS-only defaults

The catalogue preserves the authored source value and the real CSS recipe for these four public entries. CSS output remains supported. Complete portable DTCG export is omitted with a reason, and subset export reports the same paths:

| Path                    | CSS recipe     | Source value              | Portable reason                                                    |
| ----------------------- | -------------- | ------------------------- | ------------------------------------------------------------------ |
| `carousel.slide-size`   | `100%`         | `100`                     | percentage CSS value has no faithful DTCG dimension representation |
| `carousel.aspect-ratio` | `16 / 9`       | `1.7778`                  | ratio expression is not a DTCG dimension                           |
| `code-block.height`     | `auto`         | `{ value: 0, unit: rem }` | `auto` is a CSS keyword without a DTCG dimension value             |
| `spinner.indicator`     | `currentColor` | `{ text.default }`        | context-inheriting CSS keyword has no faithful literal export      |

No placeholder is used as a portable value.

## Spacing scale

The public literal spacing members are the `space.*` dimensions declared in the foundation set. Their explicit `scale: 'spacing'` membership is source metadata; aliases and unrelated radius, font and motion values remain outside the scale. Dependents are derived from actual references and trusted recipe inputs.
